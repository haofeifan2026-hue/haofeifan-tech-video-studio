# 内容驱动补画工作流

这个工作流用于已有口播粗剪或正在制作的口播项目。目标是让补充画面解释当前句子，并保持时间线可编辑、来源可追溯、生成素材可替换。

## 先建立语义覆盖表

以最终时间线转录和字幕为时间真相，不从原始脚本猜时间。逐段记录：

| 字段 | 要求 |
|---|---|
| 时间范围 | 时间码或帧范围，按完整语义起止 |
| 口播原句 | 保留实际说出的核心句，不改写成新事实 |
| 画面作用 | 证据、示例、解释、对比、情绪缓冲或章节转折 |
| 首选来源 | 用户素材、项目素材、真实截图、信息图、生成图片或生成视频 |
| 画面规格 | 比例、时长、是否保留全文、`contain`/`cover`、字幕风险 |
| 事实状态 | 已核验、用户提供或纯示意；记录核验来源或未核验边界 |
| 状态 | 已找到、待生成、已导入、已放置、已验证 |

只为需要视觉解释、具体证据或节奏变化的段落补画。真人表情和手势能完成表达的段落保持安静。口播短视频可先以每 8–15 秒一次有意义的视觉变化作为密度参考，再根据内容调整。

## 选择素材形式

按以下顺序选择，命中前一种就停止继续生成：

1. 用户提供的直接实拍、截图或产品素材。
2. 项目媒体池中已有、时间和内容都匹配的素材。
3. 可核验的真实网页、界面截图或屏幕录制。
4. 确定性信息插图：流程、容量、对比、排队、信息过载等抽象关系。
5. AI 生成图片：需要写实环境、人物或物体但没有真实素材。
6. AI 生成短视频：动作本身承担叙事，静态图加轻推近无法表达时才使用。

图片适合概念解释、证据展示和 4–8 秒插入；短视频适合动作、空间变化和过程。不要把普通静态观点升级为付费视频生成。付费生成前必须确定镜头数量、每段时长、画幅、内容和模型；用户已明确这些项目时直接执行，不重复确认。

## 相关性与事实约束

- 每个生成提示词必须引用当前口播的主体、动作或因果关系，并说明它承担的画面作用。
- 放入时间线前必须能回答“它对应哪一句口播”和“它增加了什么信息”；任一问题没有明确答案就拒绝该素材。
- 不用“泛科技城市、代码雨、发光芯片”代替具体观点。删掉素材后若不影响理解，它通常只是装饰。
- 用户素材中的文字、日期和声明不自动成为已核验事实。可以作为“用户提供说明画面”呈现，但不要在新素材中重复扩写。
- 没有可靠来源时，避免品牌标识、真实人物身份、产品界面、精确数字、价格、日期、收益和引语。用无品牌、无数字的关系图解表达概念。
- 真实产品和界面优先使用真实截图；生成的假 UI 不应伪装成产品现状。

## 画面与时间线规格

- 竖屏项目优先生成或适配为 1080x1920。主体集中在上部和中部，保留当前字幕安全区。
- 横图或长图含关键文字时，不使用会裁字的全屏 `cover`。使用 `contain`、背景延展或 `scripts/compose_vertical_still.py` 生成竖屏适配版，原文件保持不变。
- B-roll 默认放在 A-roll 上方的独立视频轨；字幕保持在其上层。不要导入素材自带的无关音频，也不要改变原始人声增益。
- 常规单段 4–8 秒。语义较短时跟随实际句子，不硬凑时长；连续多段补画之间保留真人回镜，避免长时间脱离说话者。
- 图片使用轻微推近、拉远或固定构图；淡入淡出通常 4–6 帧即可。信息图以可读性优先，不使用会让文字移动过快的动效。

## 执行顺序

1. 读取项目、最终时间线、字幕和相关转录范围。
2. 浏览媒体池，建立语义覆盖表并消除重复素材。
3. 先处理用户素材：检查像素、文字、方向和裁切；需要时生成非破坏性竖屏适配版。
4. 只为剩余缺口生成素材。每个资产使用可识别名称，记录来源和对应句子。
5. 导入同一项目，放到独立覆盖轨；先校验重叠、时长和层级，再提交。
6. 图片按内容需要添加轻推近；不为了“动起来”堆叠多个效果。
7. 刷新字幕状态并读回轨道结构、每个素材的起止帧和效果绑定。
8. 对每个插入点检查淡入、中点、淡出三个合成帧；长段再增加一帧。检查相关性、裁切、字幕、层级、黑帧和回到真人的节奏。
9. 更新剪辑分析、分镜和项目素材清单，记录素材路径、时间、来源、生成方式、事实状态和可替换项。

## 完成报告

报告实际加入的素材数量和时间位置、哪些来自用户、哪些为生成、使用了什么适配或动效、检查了哪些合成帧，以及仍未核验的信息。素材只在媒体池中、没有落入时间线或没有查看合成帧时，不得报告完成。
